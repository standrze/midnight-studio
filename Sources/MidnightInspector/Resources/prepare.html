01

From Hugging Face

Paste a model repository to download it or quantize as it arrives.

A branch, tag, or commit. Studio records the exact source commit.

Downloads one source shard, quantizes it, then deletes that temporary shard. Keeps the Q4 result. Supports dense Llama, classic Mistral, Qwen2, and Qwen3; other models use Download checkpoint.

Peak disk space includes the growing Q4 output and one source shard. A model stored in a single file still needs that whole source file temporarily.

Private models & access

Accept gated model access on Hugging Face first. Launch Studio with your existing HF_TOKEN environment variable. Tokens stay out of browser forms and job history.

02

Work with a local model

Use a downloaded checkpoint or a model already in your library.

Requires unquantized safetensors. Creates a separate checkpoint and keeps your source.

Adapter & sequence settings

Batch size is 1. Overlong examples are rejected, never silently truncated. Model compatibility is checked before the first training step.

03

Your training data

Upload separate training and validation JSONL files. Each line: {"text":"Your example here"}

For fine-tuning, use complete, model-formatted prompt-and-answer examples. For CPT, use domain text. Both optimize all next tokens; assistant-only loss and full-weight training are not included.

Up to 2 MiB and 10,000 examples per split. Studio checks the format, duplicates, and overlap between splits.

04

Preparation activity

One preparation job runs at a time. Inference and external training may still use memory; unload models in Model controls when you need the space.

Native worker setup

From the Studio project, run ./Workers/build.sh. Build the checkpoint quantizer in the sibling midnight-quantization project. These build helpers also prepare the matching Metal runtime. Worker paths can be set with --trainer-binary and --quantizer-binary when launching Studio.
